WINDOWS PACKAGING ERROR — RESOLVED
ComSpec, cmd.exe, the working directory, and normal Node spawning were valid.
The Vercel Windows builder received both a populated Path and an empty PATH.
Node's Windows child-process environment handling selected the empty PATH,
causing spawn cmd.exe ENOENT before the website build command could run.
scripts/build-vercel-local.mjs passes one populated PATH key to Vercel only.
It changes neither the parent environment nor Windows settings and always runs
the build subcommand, never deploy. Its environment regression test passes.

Reproduction/fix command (this existing cached CLI path was tested):
  node scripts/build-vercel-local.mjs "C:\Users\chadd\AppData\Local\npm-cache\_npx\67eb4586ca667318\node_modules\vercel\dist\vc.js" --cwd "<linked clean website checkout>"
The wrapper runs vercel build --prod. It does not authenticate or pull secrets.

STATIC PACKAGING CORRECTION
The first successful build exposed an actual packaging weakness: outputDirectory
'.' included reports, tests, raw API source, and the untracked legal draft ZIP.
.vercelignore alone did not exclude those files from the local builder's output.
The committed build now runs node scripts/build-website.mjs and publishes only
.website-output. The build copies an explicit list of public website assets and
generates the existing Apple/Android manifests there. API functions are packaged
separately by Vercel from api/. No routes or page behavior changed for this fix.
Generated output and recovery files are excluded from Git and upload inputs.
